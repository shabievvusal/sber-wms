# new zlp — песочница для нового дизайна

Отдельный проект **рядом** с `zlp-main-main` (не внутри него) — существующий
репозиторий не тронут, это можно свободно ломать/экспериментировать без риска
для продакшена. Оригинал лежит в `../zlp-main-main`.

Стек: React 19 + Tailwind CSS v4 + shadcn/ui (компоненты лежат в `src/components/ui`
как обычные файлы — не npm-зависимость, полностью твой код для правки).

## Что внутри

- `src/pages/shipments/` — редизайн страницы «Отгрузки» (оригинал:
  `../zlp-main-main/frontend/app/src/pages/shipments/ShipmentsPage.jsx`), уже
  практически в полном функционале: **все 27 колонок оригинальной таблицы
  реализованы как настоящие колонки** (не спрятаны за разворотом строки —
  таблица просто скроллится по горизонтали), плюс сортировка по клику на
  заголовок. Вкладки «По маршрутам»/«По водителям»/«По ЦФЗ», модалки «Загрузить
  из WMS»/«Отчёт», редактирование маршрута, лайтбокс с фото. «Коды ЦФЗ» — фича
  снята за ненадобностью (была отдельная модалка, теперь её нет). Что осталось
  сознательно не перенесено — см. `PLAN.md`. Ходит в **тот же бэкенд**, что и
  основной фронт (см. proxy в `vite.config.js`).
  Если бэкенд не запущен — запрос падает, и страница сама переключается на
  демо-данные из `src/lib/mockRoutes.js` (5 маршрутов на все статусы: не
  обработан, в пути, ждёт подтверждения, завершён, с расхождением по количеству,
  плюс демо-водители/ЦФЗ для остальных вкладок) с явным баннером «Бэкенд
  недоступен — показаны демо-данные». Действия в этом режиме меняют только
  локальный стейт, ничего никуда не отправляют. Как только бэкенд поднят —
  обычный `npm start` в `backend/`, следующий запрос сам подхватит настоящие
  данные, баннер уйдёт.
- `src/components/ui/date-picker.jsx` — единый `DatePicker`/`DateRangePicker`
  (Popover + Calendar на `react-day-picker`, RU-локаль) вместо старого кастомного
  `DatePicker.jsx` на порталах и вместо нативного `<input type="date">`, который
  был здесь временной заглушкой. Фильтр периода на странице теперь один контрол
  с одним триггером, а не два поля + отдельная кнопка сброса.

## Запуск (нужно сделать один раз руками — в этой машине нет node/npm)

```bash
cd "new zlp"
npm install
npm run dev
```

Backend должен быть запущен отдельно из `zlp-main-main` (как обычно — `npm start`
в `backend/`, или `docker compose up`) на порту из `PORT` (по умолчанию 3000).
Этот сервер поднимется на **5174**, оригинальный `frontend/app` — на 5173,
конфликта нет, можно держать открытыми оба и сравнивать.

## Дальше

Если подход одобряешь — по одной странице переносим остальные:
1. Переносим страницы в порядке убывания размера/боли: `SettingsPage` (1930 строк) →
   `ConsolidationPage` → `SuppliesPage` → `MonitorPage`. Везде, где раньше был
   `DatePicker.jsx` или `<input type="date">` — подключаем `date-picker.jsx`
   отсюда, чтобы календарь был один на весь проект.
2. Когда весь `frontend/app` переехал — этот проект становится основным фронтендом,
   `zlp-main-main/frontend/app` выводится из эксплуатации.

Подробный статус по каждому пункту — в `PLAN.md`, обновляется по ходу работы.

При такой миграции не потеряется исправление второй проблемы из твоего запроса —
пересчёт статистики на фронте (`statsCalc.js`) переносится на бэкенд отдельным
шагом, независимо от вёрстки: сначала бэкенд начинает отдавать уже готовые цифры,
потом страницы просто перестают их пересчитывать сами.
