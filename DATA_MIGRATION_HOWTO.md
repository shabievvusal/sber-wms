# Как достать реальные данные с основного проекта (хост) и перенести сюда

Инструкция для вас — что сделать на удалённом сервере (по SSH), чтобы
вытащить файлы наружу из контейнера, а потом скачать их через FileZilla
на свой компьютер и положить в `migration-staging/` этого проекта.

Данные бывают двух видов, и способ извлечения для них разный:

- **Файловые** (JSON-файлы внутри контейнера) — их видно только внутри
  контейнера (см. «Почему нельзя просто зайти по FileZilla в контейнер»
  ниже), нужен `docker cp`.
- **В Postgres** (если на сервере включён `USE_PG=true`) — некоторые
  домены (сотрудники, маршруты РК, ТСД) могут храниться не в файлах, а в
  базе — тогда `docker cp` их не покажет вообще, нужен `psql`-экспорт.

Сначала — шаг 0, чтобы понять, какой случай ваш.

---

## Шаг 0. Проверить, что где хранится (USE_PG)

По SSH на сервере, в папке проекта (там же, где `docker-compose.yml`):

```bash
cat .env | grep USE_PG
```

- `USE_PG=false` (или строки нет вообще) → все домены ниже — **файловые**,
  идёте по «Способу А».
- `USE_PG=true` → сотрудники/маршруты РК/ТСД, скорее всего, **в
  Postgres** (у этих трёх доменов есть Postgres-версия — `empl-pg.js`/
  `route-rk-pg.js`/`tsd-pg.js`), идёте по «Способу Б» для них. Статистика
  (`backend/data/<date>/<HH>.json`) при этом всё равно **файловая** в
  любом случае — этот домен на Postgres в оригинале не переведён.

Если сомневаетесь — можно проверить оба способа, лишним не будет: если
файл окажется пустым/устаревшим, просто не используем его.

---

## Способ А — файлы внутри Docker-контейнера (`docker cp`)

### Почему нельзя просто зайти по FileZilla в контейнер

Реальные данные (`backend/data/`, `vs-users.json`, `config.json`,
`empl.csv`, `uploads/`) внутри контейнера — это symlink'и на именованный
Docker-том `node-persist` (см. `docker-entrypoint.sh`). Сам том хранится
Docker'ом отдельно от файловой системы хоста — обычным SFTP/FileZilla
внутрь контейнера или в том зайти нельзя вообще, у контейнеров нет
SSH/SFTP-сервера. Единственный способ достать оттуда файлы — через
`docker cp`, который копирует их на файловую систему ХОСТА (не
контейнера), а вот файловую систему хоста FileZilla уже видит нормально.

### 1. Найти имя контейнера

```bash
docker ps
```

Ищите строку с образом `wms-node` (или колонку NAMES вида
`<папка-проекта>-node-1` / `<папка-проекта>_node_1` — зависит от версии
Docker Compose). Дальше подставляйте это имя вместо `<container>`.

### 2. Скопировать персистентный том на хост

```bash
mkdir -p ~/extracted-persist
docker cp <container>:/app/persist ~/extracted-persist
```

После этого в `~/extracted-persist/persist/` на хосте появится обычная
папка с файлами:

```
persist/
├── data/                  ← вся статистика по сменам (главное, что нужно)
│   ├── 2026-07-10/
│   │   ├── 10.json
│   │   ├── 11.json
│   │   └── ...
│   ├── route-rk.json      ← маршруты РК (только если USE_PG=false)
│   ├── rk-photos/         ← фото по маршрутам
│   └── ...
├── vs-users.json          ← пользователи панели (логины/роли)
├── config.json            ← настройки авто-сбора (обычно не нужен)
├── empl.csv               ← сотрудники (только если USE_PG=false)
└── uploads/                ← прочие загруженные файлы
```

### 3. Проверить, что скопировалось

```bash
ls -la ~/extracted-persist/persist/
du -sh ~/extracted-persist/persist/*
```

Если `empl.csv` весит 0 байт и `route-rk.json` нет вообще — это нормально
при `USE_PG=true`, эти два домена смотрите через Способ Б ниже.

## Способ Б — если данные в Postgres (`USE_PG=true`)

Если для нужного домена (сотрудники/маршруты РК/ТСД) на сервере
`USE_PG=true`, `docker cp` их не покажет — они в базе, не в файлах.
Есть два варианта извлечь: через собственный API проекта (проще и
надёжнее) или напрямую через `psql` (запасной вариант).

### Б.1 — через собственный API проекта (рекомендуется, но не для всех доменов)

Проще всего — прямо на сервере обратиться к уже работающему приложению
(оно само знает, читать из файлов или из Postgres, и всегда отдаёт
готовый JSON в одном и том же формате — том самом, что мы уже успешно
перенесли для сотрудников: `{"employees":[{"executorId":...}]}`).
Похоже, `empl.json` был получен именно так.

```bash
# Порт возьмите свой (обычно 3009, см. PORT в .env)
curl http://localhost:3009/api/employees > ~/empl.json
```

Это работает без входа в систему — `/api/employees` открыт без сессии.
А вот `/api/rk/routes` и `/api/tsd-assignments` **требуют сессию
(`vsSessionRequired`)** — простой `curl` без входа получит `401`, не
данные. Два варианта:

1. Войдите в панель в браузере на этом сервере, откройте DevTools →
   Application/Storage → Cookies → скопируйте значение куки `vs_sid`,
   подставьте в запрос:
   ```bash
   curl -H "Cookie: vs_sid=<значение_куки>" http://localhost:3009/api/rk/routes > ~/routes.json
   curl -H "Cookie: vs_sid=<значение_куки>" http://localhost:3009/api/tsd-assignments > ~/tsd_assignments.json
   ```
2. Либо сразу используйте Б.2 (psql) для этих двух доменов — не нужен
   вход, но поля будут `snake_case` (см. оговорку ниже).

Также учтите: `/api/tsd-assignments` отдаёт только АКТИВНЫЕ (не
сданные) выдачи ТСД, не всю историю — если нужна полная история,
доставайте из Postgres напрямую (Б.2).

### Б.2 — напрямую через psql (запасной вариант)

Работает всегда, но колонки в базе — `snake_case` (`executor_id`, не
`executorId`), а мои скрипты-переносчики ждут `camelCase` (как в
`empl.json`, полученном через API) — если пойдёте этим путём, **пришлите
мне первые несколько строк того, что получилось**, прежде чем класть в
`migration-staging/` — подгоню скрипт-перенос под реальный формат, не
буду гадать вслепую.

```bash
docker compose exec postgres psql -U zlp -d zlp -c "\dt"
```

Покажет список таблиц. Дальше для конкретной таблицы:

```bash
docker compose exec postgres psql -U zlp -d zlp -t -A -c \
  "SELECT json_agg(row_to_json(t)) FROM <имя_таблицы> t" \
  > ~/<имя_таблицы>.json
```

## Шаг 2. Скачать через FileZilla

1. Подключитесь к серверу как обычно (SFTP, тот же логин/пароль или
   ключ, что и всегда).
2. Перейдите в домашнюю папку (`~`) или туда, куда клали файлы —
   `~/extracted-persist/persist/` и/или `~/empl.json`, `~/routes.json`,
   `~/tsd_assignments.json`.
3. Скачайте нужные файлы/папки к себе на компьютер.

## Шаг 3. Положить файлы сюда

Скачанные файлы кладите в:

```
b:\рабочий стол\new zlp-backend\migration-staging\
```

(та же папка, куда уже клали `empl.json` — сотрудники им уже перенесены,
второй раз для того же файла ничего страшного, скрипт безопасно
перезапишет те же записи).

После того как файлы на месте — напишите мне, что именно положили
(например «положил persist/data целиком» или «положил routes.json»), и
я посмотрю их реальную структуру и подгоню/напишу перенос-скрипт под
конкретно этот файл, прежде чем что-либо писать в базу — так же, как
уже было сделано для сотрудников.
